# --- 11. UART for SBUS -- THE BIGGEST GAP, nothing in the repo does this ------
# sbus_publisher.py:68 opens /dev/ttyAMA0 @100000 baud 8E2 (lines 400-407).
# A fresh Pi 5 has NO usable /dev/ttyAMA0 until all four steps below are done.
sudo sh -c 'printf "\nenable_uart=1\ndtoverlay=disable-bt\n" >> /boot/firmware/config.txt'
sudo systemctl disable --now serial-getty@ttyAMA0.service
sudo usermod -aG dialout $USER
sudo reboot          # required: config.txt + group membership both need it
# [CHECK] after reboot:  ls -l /dev/ttyAMA0   &&   groups | grep dialout
# NOTE: SBUS is inverted -- an external inverter or the SIYI receiver must feed it.

# --- 11b. USB current cap -- CAN adapters go RED at boot with the BMS FTDI TTL --
# We power the Pi 5 from a 5V/10A buck straight into USB-C. A plain buck does NOT
# do USB-C PD negotiation, so the firmware defaults the USB ports to a 600 mA TOTAL
# cap. At boot the 2 USB-CAN adapters (can_drive/can_arm) + the FTDI TTL power up
# together, exceed 600 mA, and the firmware current-limits -> a CAN adapter browns
# out (red). (Plugging the TTL in AFTER boot dodges the simultaneous inrush.)
# The 10A buck can supply it -- just tell the firmware it is allowed to:
sudo sh -c 'printf "\nusb_max_current_enable=1\n" >> /boot/firmware/config.txt'
sudo reboot          # required: config.txt change
# [CHECK] after reboot (with the TTL plugged in at boot):
#   vcgencmd get_config usb_max_current_enable    # -> usb_max_current_enable=1
#   ip link show can_drive && ip link show can_arm # both UP, no red
#   dmesg | grep -iE "over.?current|usb.*current"  # no current-limit events
# NOTE: the BMS now uses a hardware UART (step 11c) instead of a USB FTDI, so the
# extra USB device is gone -- that alone removes it from the boot USB-current budget.

# --- 11c. BMS UART -- JK-BD BMS on the Pi 5 hardware UART (GPIO 12/13) ----------
# battery_bms.py (ros2_canbus 'bms' node) reads the BMS over UART instead of an
# FTDI USB-TTL. Wiring: BMS TX -> Pi GPIO13 (RXD), BMS RX -> Pi GPIO12 (TXD),
# GND common, 3.3 V logic.
# On the Pi 5, GPIO 12/13 is uart4-pi5 -> /dev/ttyAMA4 (NOT uart5/ttyAMA5):
sudo sh -c 'printf "\ndtoverlay=uart4-pi5\n" >> /boot/firmware/config.txt'
sudo reboot          # required: config.txt change
# [CHECK] after reboot:
#   ls -l /dev/ttyAMA*        # expect /dev/ttyAMA4 for the BMS UART (GPIO 12/13)
# If it enumerates as a different ttyAMA, run the bms node with BMS_PORT set,
# e.g. export BMS_PORT=/dev/ttyAMA5
# Free the port from a login console if one grabbed it:
#   sudo systemctl disable --now serial-getty@ttyAMA4.service
# [CHECK]:  ros2 run ros2_canbus bms   # prints 'SOC nn %  vv.vv V'

# --- 11d. CAN passwordless sudo -- so robot_startup.sh can bring up CAN at boot -
# robot_startup.sh runs as the user (systemd service, no TTY) and calls
# `sudo can_bringup.sh`. Without a NOPASSWD rule that fails at boot ("a password
# is required") and CAN never comes up. Grant NOPASSWD for just that script:
echo "${USER} ALL=(root) NOPASSWD: ${HOME}/ros2_ws/src/necessary_codes/can_bringup.sh" \
  | sudo tee /etc/sudoers.d/can_bringup
sudo chmod 440 /etc/sudoers.d/can_bringup
sudo visudo -c            # validate; must report the file "parsed OK"
# [CHECK]:  sudo -n ${HOME}/ros2_ws/src/necessary_codes/can_bringup.sh  # no password prompt

 KNOW THIS BEFORE YOU EXPECT THE ARM TO MOVE
==============================================================================
 part_assembly_for_urdf.ros2_control.xacro:8-9 says outright:
   "By default, set up controllers for simulation. This won't work on real hardware"
   <plugin>mock_components/GenericSystem</plugin>

 separate path. Confirm that split is intentional before deploying.

 Not covered here (CAN stack, out of scope): the username jontro_soinik_2_0-2 is
 hardcoded in robot-startup.service:10,11,13, controller_config.json:2,
 Network_Lib.py:18 and Load_Settings_Lib.py:16. Those read config from the SOURCE
 tree, so ~/ros2_ws/src/ must exist at that exact path even on a deployed Pi.
 The arm stack itself is username-clean -- any username works for 14a-14d.
